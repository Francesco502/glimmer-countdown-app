TimeAPK 功能优化改动方案
> 本文作为后续迭代的执行蓝本，只描述「要做什么 + 怎么做」，不真正改代码。
1. 提醒时间更灵活（支持具体时间点）
目标
在「提前 N 天」的基础上，让用户可以选择一天中的具体时间（如 08:00 / 12:00 / 18:00）。
让提醒逻辑统一走「目标日期 - 提前 N 天 + 指定时间点」。
现状简述
Event 已有：remindEnabled、remindDaysBefore、reminderTimeMinutesOfDay（分钟数）。
编辑页已有「提前 0/1/3/7 天」Chip 和「提醒时间」预设 Chip（0/6/8/9/12/18 点）。
ReminderScheduler / ReminderWorker 已实现按日期和提醒配置计算触发时间。
规划改动
数据层
确认 Event 中字段是否已满足需求：
remindEnabled: Boolean
remindDaysBefore: Int（提前 N 天）
reminderTimeMinutesOfDay: Int（一天中的分钟数）
如果字段已存在，无需变更表结构；如缺少则：
为 Event 增加 reminderTimeMinutesOfDay 字段，默认 8:00（480 分钟）。
Room version +1，并在迁移中为旧数据填充默认值（见第 3 节）。
UI 层（编辑页 EventEntryScreen）
保持当前 Chip 方案，但补全/优化：
「提前 N 天」Chip：0/1/3/7 天。
「提醒时间」Chip：8:00 / 12:00 / 18:00（可保留现有方案）。
可选增强：
若后续需要更高自由度，可引入时间选择器（TimePicker 或简单列表），目前先用固定 Chip 控件即可。
提醒调度逻辑
确认 scheduleReminder(...) 的时间计算逻辑：
目标触发时间：event.date(零点) - remindDaysBefore + reminderTimeMinutesOfDay。
确保以下情况正确：
提前 N 天后仍在未来（若已过期则不再安排提醒）。
用户关闭 remindEnabled 时取消已有提醒。
2. 桌面小部件交互增强
目标
点击小部件中的具体一行跳转到对应事件详情。
小部件中区分「已过期 / 快到期」视觉状态（颜色或小角标）。
现状简述
已有 CountdownAppWidgetProvider，显示最近若干个事件。
目前小部件整体点击只打开 App 首页。
规划改动
单行点击跳转详情
在 RemoteViews 构建列表项时：
为每一行设置不同的 PendingIntent，Intent 中携带 eventId。
目标 Activity：MainActivity，在导航层根据 eventId 决定打开 DetailScreen。
导航层（MainActivity / NavHost）：
支持从 Intent extras 读取 eventId，如果非空则直接导航到详情。
小部件状态展示
在小部件数据计算时，增加：
isPast：已过期。
isSoon：快到期（如距离今天 ≤ 3 天）。
UI 表现建议：
已过期：使用灰色文字 / 灰底，或加「已过」角标。
快到期：高亮底色或在文字右上角加一个小圆点（红/橙色）。
将 isPast / isSoon 转为：
不同的 setTextColor / setViewVisibility / setImageViewResource 控制。
3. Room 正式迁移 & 数据安全
目标
摆脱 fallbackToDestructiveMigration，版本升级不再清空用户数据。
为已有版本编写显式 Migration。
现状简述
Room 当前 version = 2（或最新），且使用 fallbackToDestructiveMigration。
已新增字段：repeatType、remindDaysBefore、remindEnabled、createdAt 等。
规划改动
移除破坏性迁移
DataBase 构建中移除：
.fallbackToDestructiveMigration()。
改为注册 addMigrations(MIGRATION_1_2, MIGRATION_2_3, ...)。
补写迁移脚本
针对已经上架的版本链路，补足：
MIGRATION_1_2：为 Event 表新增上述字段，设置默认值：
repeatType 默认「不重复」。
remindDaysBefore 默认 0。
remindEnabled 默认 0 (false)。
createdAt 默认当前时间或 date。
若已有 version=2 再新增字段，则继续 MIGRATION_2_3。
在迁移中使用：
ALTER TABLE Event ADD COLUMN ... 方式，保证数据保留。
测试
准备本地数据库文件（旧版 schema），模拟升级：
启动旧版本 -> 创建若干事件 -> 升级到新版本 -> 验证数据仍在。
4. 多语言与文案打磨
目标
统一所有界面文案到 strings.xml / values-zh / values-en。
梳理中英文语气、长度、占位符，让 UI 更精致统一。
现状简述
已存在 values-zh / values-en。
部分界面可能仍有硬编码字符串或文案风格不统一。
规划改动
文案收拢
逐屏排查：
首页、详情、新建/编辑、设置、小部件等。
将所有硬编码中文/英文移入 strings.xml：
使用占位符 %1$s / %d 替代拼接。
例如分享文案、删除确认文案、空状态提示等。
多语言一致性
对中英文分别优化：
中文：尽量简短、自然口语化，避免生硬直译。
英文：注意长度控制，避免在按钮/Chip 上过长文字。
对数值+单位的写法统一：
如：「还剩 X 天」「X days left」，"%1$d 天" / "%1$d days"。
规范检查
确保：
所有文本均通过 stringResource(...) 获取。
小部件中的 text 也使用资源字符串。
5. 左滑删除真正落地（SwipeToDismissBox）
目标
在首页列表实现真正的左滑删除交互。
配合现有 Snackbar 撤销能力，形成完整的删除体验。
现状简述
设计中已提到 SwipeToDismissBox。
当前版本因 BOM/依赖原因未完全启用，改为长按弹出删除菜单。
Home 列表代码中已存在 rememberSwipeToDismissBoxState 等初步实现。
规划改动
依赖检查
确认 Compose BOM 版本是否包含稳定版 SwipeToDismissBox。
如需要，升级 Compose BOM 到推荐版本，并跑一遍全局编译/预览。
UI 行为
对每个 EventCard 外包一层 SwipeToDismissBox：
允许 EndToStart（右向左）方向删除。
backgroundContent 绘制红色删除背景 + 垃圾桶 icon。
confirmValueChange 中：
弹出 Snackbar 提示「已删除」，附带「撤销」按钮。
如点击撤销，则调用 restoreEvent 还原。
与长按菜单关系
可保留长按菜单作为补充（提供「编辑」「删除」）。
左滑快速删除，长按更精细操作。
6. 卡片/按钮的按压反馈统一
目标
所有可点击区域在按下时都有一致的 scale 动效。
统一「按下感」，提升整体精致度。
现状简述
已有部分组件使用 AnimationSpecs.springButton + animateFloatAsState（FAB、颜色 Chip、设置行等）。
仍有部分可点击元素只改变颜色，没有缩放反馈。
规划改动
建立统一封装
在主题或公共 UI 包中封装：
PressScaleWrapper 或 Pressable 组件：
内部使用 MutableInteractionSource + collectIsPressedAsState()。
按下时 scale=0.96f~0.98f，抬起恢复。
或者提供统一 Modifier：
Modifier.pressScale(interactionSource, scaleDown = 0.96f)。
逐个替换
扫描以下组件，统一应用：
首页 EventCard 点击区域。
详情页底部按钮（编辑/删除/分享）。
设置页可点击行（如导出/导入）。
颜色 Chip、分类 Chip、FAB 等已有实现做成统一封装。
7. 空列表状态 & FAB 引导强化
目标
在没有任何事件时，引导用户「点击 + 添加」。
通过 FAB 轻微动效吸引注意，提升第一次使用的转化。
现状简述
已有空列表提示和一个正常大小的 FAB。
FAB 在空状态下已有轻微 scale 动画（如 1.08f）。
规划改动
空状态下 FAB 动效升级
针对 displayedList.isEmpty()：
保留或增强现有 animateFloatAsState，让 FAB 有轻微呼吸（scale 在 1.0 ~ 1.08 之间往返）。
动画节奏较慢（2~3 秒一循环），避免过于「跳动」。
空状态文案
确保空状态区域内：
主文案：「还没有任何倒计时」。
副文案：「点击下方 + 添加第一个」。
两者均放入 strings.xml，中英文优化。
8. 提醒精度显示的控制（是否显示小时）
目标
给用户一个设置项：
「只看天数」
「天 + 小时」
避免部分用户被过多信息打扰。
现状简述
EventUiState 已有 hoursRemaining。
首页卡片在特定条件下会显示「X 小时」文案。
设置页已有「显示小时」相关配置（showHours）。
规划改动
设置项确认 & 优化
在 SettingsScreen 中已有：
showHours + Switch + 文案「精确到小时」。
可优化文案和说明：
标题：「显示剩余小时」。
描述：「开启后，在倒计时接近时，会显示剩余小时数。」
首页展示逻辑收敛
卡片显示小时的逻辑统一依赖 showHours：
当 showHours == true 且事件未过期、hoursRemaining > 0 时才显示「X 小时」。
确保所有使用 hoursRemaining 的地方均参考此设置。
总体实施顺序建议
Room 迁移 & 数据安全（第 3 节）
提醒时间更灵活（第 1 节）
左滑删除 + 撤销（第 5 节）
小部件交互增强（第 2 节）
多语言与文案打磨（第 4 节）
按压反馈统一 & 空状态引导（第 6、7 节）
提醒精度显示控制（设置项微调）（第 8 节）
