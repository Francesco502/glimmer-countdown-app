# 卡片日期显示切换（首页/详情）改动规格

## 1. 背景与问题

当前卡片的「时间差展示」会根据事件是否重复（`repeatType`）走不同显示逻辑，且用户无法在首页卡片或详情页快速切换展示方式。需要改成：**首页卡片、详情页中点击“日期/时间差区域”即可在两种展示之间切换**，并且**展示文案/形式要遵循用户对事件“是否重复”的设置**。

## 2. 目标（Goals）

- 在 **首页卡片** 与 **事件详情页** 中，用户点击「日期/时间差」可在两种展示之间切换（保留两种模式）。
- **非重复事件（REPEAT_NONE）**：
  - 卡片显示为“已经…”口径（详见 4.1 规则）
  - 支持两种切换：
    - 模式 A：`已经 X 年 X 月 X 天`
    - 模式 B：`已经 XX 天`
- **重复事件（repeat != none）**：
  - 卡片显示为“还有…”口径（详见 4.2 规则）
  - 支持两种切换：
    - 模式 A：`还有 XX 天`
    - 模式 B：`还有 X 年 X 月 X 天`
- 切换方式一致：**点日期/时间差区域切换**（首页、详情一致），无需进入设置。

## 3. 非目标（Non-Goals）

- 不在本次改动中新增第三种展示模式。
- 不在本次改动中引入“按事件单独记忆显示模式”的复杂配置（见 5.2 可选项）。
- 不在本次改动中改动事件的重复类型含义（仍由用户在编辑事件时配置）。

## 4. 交互与显示规则

### 4.1 非重复事件（REPEAT_NONE）

**规则（本次规格的解释与落地建议）**

- **基准口径**：以事件目标日期与今天的关系决定“已经/还有”：
  - 若目标日期在今天之前：显示 `已经 ...`
  - 若目标日期在今天或未来：显示 `还有 ...`

> 说明：用户原话提到“若非重复则显示已经XX天格式”。但为避免未来日期出现“已经”，这里将“已经/还有”与时间方向绑定；两种切换仅影响“天数 vs 年月日”格式，不改变时间方向语义。

**两种展示（点击切换）**

- **模式 A（YMD）**：
  - 过去：`已经 X 年 X 月 X 天`
  - 未来：`还有 X 年 X 月 X 天`
- **模式 B（Days）**：
  - 过去：`已经 XX 天`
  - 未来：`还有 XX 天`

### 4.2 重复事件（repeatType != none）

**规则**

- 重复事件在首页/详情的目标日期按“下一次发生日”计算（现有逻辑已存在）。
- **统一使用“还有 …”口径**（因为展示的是距离下一次发生还剩多久）。

**两种展示（点击切换）**

- **模式 A（Days）**：`还有 XX 天`
- **模式 B（YMD）**：`还有 X 年 X 月 X 天`

> 说明：用户原话为“重复：1还有XX天，2还有X年X月X天”，这里与之完全一致。

### 4.3 点击区域与反馈

- **点击区域**：卡片上显示日期/时间差的那一行（或日期 + 剩余/已过摘要区域），详情页同理。
- **反馈**：
  - 切换应立即更新显示（不弹 Toast 也可）。
  - 可选：轻微的淡入淡出/数字滚动动画（不影响本次核心需求）。

## 5. 状态与持久化

### 5.1 推荐方案：全局记忆（简单、可预期）

- 新增用户偏好：`dateDeltaDisplayMode`
  - `0`：Days 模式优先（用于重复事件默认“还有XX天”；非重复事件默认“已经/还有XX天”）
  - `1`：YMD 模式优先（用于非重复事件默认“已经/还有X年X月X天”；重复事件默认“还有X年X月X天”）
- **点击切换会写回该偏好**，因此首页与详情保持一致。

优点：
- 逻辑简单、实现快、用户学习成本低。

### 5.2 可选方案：按事件记忆（更灵活，后续迭代）

- 为每个事件记录一个显示模式（例如 Room 增加字段或 DataStore Map）。
- 用户在某个事件切换后，只影响该事件。

缺点：
- 状态管理、迁移成本更高；不建议作为本次首版。

## 6. 计算与格式化要求

### 6.1 “XX 天”计算

- 基于 `ChronoUnit.DAYS.between(today, target)`（与现有 `daysRemaining`/`daysLeft`/`daysPassed` 保持一致）。

### 6.2 “X 年 X 月 X 天”计算（YMD 差值）

- 使用 `java.time.Period.between(start, end)` 计算年月日差值。
- 约束：
  - 对“还有”场景：start = today，end = targetDate（下一次发生日或目标日）
  - 对“已经”场景：start = targetDate，end = today
- 显示约定：
  - 年/月/天为 0 的部分可省略或保留（需要统一风格；建议：保留非零单位，至少显示天）。

## 7. 受影响页面与组件

- 首页：`HomeScreen` 中卡片时间差显示区域
- 详情：`DetailScreen` 的日期/时间差展示区域
- 偏好：`UserPreferencesRepository`（新增 dateDeltaDisplayMode Flow + setter）
- 字符串资源：增加 “已经/还有 + 年月日/天数” 相关模板（中英）

## 8. 验收标准（Acceptance Criteria）

- 在首页卡片点击日期/时间差，展示在两种模式间切换，且切换后进入详情页保持一致（全局记忆方案）。
- 对非重复事件：
  - 过去日期显示“已经 …”
  - 未来日期显示“还有 …”
  - 两种模式切换仅影响“天数 vs 年月日”
- 对重复事件：
  - 始终显示“还有 …”
  - 两种模式在“还有 XX 天”与“还有 X 年 X 月 X 天”间切换
- 切换不影响事件排序、过滤、提醒调度等既有功能。

## 9. 测试建议（手测清单）

- 非重复 + 未来（例如 +10 天）：
  - Days：还有 10 天
  - YMD：还有 0 年 0 月 10 天（或“还有 10 天”，视省略规则）
- 非重复 + 过去（例如 -10 天）：
  - Days：已经 10 天
  - YMD：已经 0 年 0 月 10 天（或“已经 10 天”）
- 每年重复（例如 2020-09-13）：
  - Days：还有 N 天（到下一次 09-13）
  - YMD：还有 X 年 X 月 X 天
- 首页切换后进入详情，再返回首页，状态一致。
