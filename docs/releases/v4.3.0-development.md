# 4.3.0 开发与验证记录

日期：2026-11-09。4.3.0 / versionCode=30 将原计划的维护修复与技术升级合并为一个版本，已于 2026-11-09 正式发布。本文档记录实现、CI 与最终标签构建证据；物理真机未执行，按发布负责人授权如实记录。

## 范围

### 平台正确性

- 小组件跨天刷新：`WidgetDateBoundaryScheduler` 在用户已授予精确闹钟时使用 `setExactAndAllowWhileIdle`，否则保留非精确闹钟；`WidgetRefreshReceiver` 在同一 `goAsync` 生命周期内刷新列表与单事件组件；`DATE_CHANGED` 同时刷新两类组件；`MainActivity.onResume` 补刷一次。
- 自更新：`UpdateInstaller` 解析 GitHub Release 的 `sha256:` 资产摘要，在原子替换前校验；只接受 `https://github.com/` 且以 `.apk` 结尾的资产地址。下载移到 `TimeApplication` 应用级作用域，通过 `UpdateDownloadState` 暴露进度与结果；后台完成时保留安装包，回到前台自动安装并提示。
- 通知频道在 `TimeApplication.onCreate` 统一创建；冷启动重排在 15 分钟内不重复触发。
- 备份仅在具备加密能力时上传云端；图片清理增加 7 天宽限期的孤儿回收；EXIF 方向补齐镜像/转置；分享缓存 24 小时清理。
- DataStore 配置 `ReplaceFileCorruptionHandler`，损坏偏好回退默认值。

### 数据与一致性

- 编辑保存改为只更新用户可编辑列（`EventDao.updateEventUserFields`），0 行时返回明确的“事件已被删除”；日历同步字段改由 `updateEventScheduleFields` 单独写回。
- 导入改为单一事务：分类与事件一起提交，副作用（提醒/日历）在提交后执行。
- Room v12：新增 `index_events_date`、`index_events_category`，迁移 11→12 注册并导出 schema。
- JSON 导出页新增“配图不随 JSON 导出”的说明（zh/en）。

### 界面与无障碍

- 详情页改为真正的导航目的地（`Routes.Detail/{eventId}`）：手机/紧凑屏由导航返回栈与系统返回接管，进入与返回走统一转场；宽屏仍保留列表 + 详情双栏（右侧面板）。删除撤销的 Snackbar 提升到 NavHost 之上，详情页删除后返回列表仍可撤销。
- 首页从 1349 行拆分为 `HomeScreen.kt`（列表/月历/滚动与状态，约 726 行）+ `HomeChrome.kt`（工具栏、搜索框、溢出菜单、工具面板、一次性提示、添加按钮、返回处理）。
- 详情页深浅色改用 `MaterialTheme.colorScheme.background` 亮度判断，强制主题生效。
- 详情浮层打开时首页 `clearAndSetSemantics`，退出无障碍树。
- 事件卡片把“切换时间显示”暴露为 `CustomAccessibilityAction`；列表时间区最小高度 48dp；筛选 chip 使用 `minimumInteractiveComponentSize`；搜索框改为 `heightIn(min = 48.dp)`。
- 深色启动页补齐 `values-night` 的 `splash_bg`；新增 `localeConfig` 与 Android 13+ per-app language 双向同步；小组件配置 Activity 跟随应用内语言。

### 依赖与工程化

- Compose BOM 2024.02.00 → 2026.03.01（Compose 1.6 → 1.10，Material3 1.2 → 1.4）；core-ktx 1.12.0 → 1.17.0；activity-compose 1.8.2 → 1.12.4；lifecycle 2.7.0 → 2.10.0（新增 `lifecycle-runtime-compose`）；navigation 2.7.5 → 2.9.8；work 2.9.0 → 2.11.2；datastore 1.0.0 → 1.2.1；exifinterface 1.3.7 → 1.4.2；room 2.8.4 → 2.8.5。

- 删除未使用的 `material-icons-extended`；R8 规则不再整包 keep Compose/OkHttp/DataStore/Room。

## CI 首轮失败与修复（2026-11-09）

首轮 PR CI（run `42589191248`）在 API 26/31/36 均失败，暴露两个真实问题，均已修复：

1. **Compose 1.10 与排序库二进制不兼容（严重）**：`org.burnoutcrew.composereorderable:reorderable:0.9.6`
   调用 `LazyItemScope.animateItemPlacement`，而 Compose 1.10 已移除该方法。设备上
   `ReorderableItem` 抛 `NoSuchMethodError`，首页直接崩溃；表现为 6 个 UI 仪器测试失败和 runtime smoke
   的 “UI dump has no visible target-package nodes”。
   修复：将该库 0.9.6 的 Kotlin 源码内置到 `app/src/main/java/org/burnoutcrew/reorderable/`
   （Apache-2.0，保留原版权头与 NOTICE），把两处 `animateItemPlacement()` 改为 `animateItem()`，
   并移除 Maven 依赖。
2. **仪器测试序列化库冲突**：`androidx.room:room-testing:2.8.5` 的迁移序列化器需要
   `kotlinx-serialization 1.8.1`，而 lifecycle 2.10 只把 1.7.3 带进 app 运行时；AGP 的 consistent
   resolution 让 androidTest 也固定在 1.7.3，4 个 Room 迁移测试抛
   `AbstractMethodError: GeneratedSerializer.typeParametersSerializers()`。仅在 androidTest 强制
   1.8.1 不够（app 运行时的旧版本仍会先被加载）。
   修复：保留 Room 2.8.5，并在 **app 运行时**显式声明
   `kotlinx-serialization-core/json:1.8.1`，让 app APK 与测试 APK 使用同一版本；删除测试侧强制。

修复后本地复验：vendor 代码编译通过、双渠道单测通过、三渠道 lint 0 error、androidTest 编译通过；
第二轮 CI 待执行。
