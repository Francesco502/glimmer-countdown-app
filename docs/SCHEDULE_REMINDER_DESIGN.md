# 日程提醒方案说明

## 目标

- 在 **APP 内** 设置提醒：**提前 N 天**（如 0/1/3/7 天） + **当天几点提醒**（如 8:00、9:00）。
- 可选将上述提醒 **同步到系统日程**（多数手机在「日历」中展示日程），由系统在指定时间通过 **通知栏** 等方式提醒用户。
- 纪念日、生日等分类共用同一套「提前 N 天 + 几点」设置，并均可选择是否同步到日程。

## 概念区分

| 概念 | 说明 |
|------|------|
| **日历 (Calendar)** | 系统日历应用，用于显示月视图、事件列表。 |
| **日程 (Schedule / 议程)** | 通常指「某天某时要做的事」；在 Android 上多数厂商用 **日历事件 + 提醒** 实现，日程会在日历里显示。 |
| **本方案** | 在 APP 里配置「提前 N 天、几点提醒」，并可选 **写入系统日历的一条“日程”**，由系统在那一刻弹出通知。 |

即：**在 APP 里设置提醒时间，通过写入系统日程，借助系统日程的提醒能力在通知栏提醒。**

## 数据与交互

### 已有能力（保持不变）

- **提前天数**：`remindDaysBefore`（0=当天，1/3/7 等）。
- **提醒时刻**：`reminderTimeMinutesOfDay`（如 480 = 8:00）。
- **是否开启提醒**：`remindEnabled`。
- 应用内通过 **WorkManager** 在「目标日 − N 天」的「设定时刻」触发 **应用内通知**。

### 新增能力

- **是否同步到系统日程**：`syncToScheduleEnabled`（默认 true）。
- **系统日程事件 ID**：`scheduleEventId`（写入日程后由系统返回，用于后续更新/删除）。

当 `remindEnabled && syncToScheduleEnabled` 时：

1. 计算提醒时刻：**目标日期的“下次发生日” − N 天**，当天的 **设定时刻**（与现有 `ReminderScheduler` 一致，农历生日用「下次农历发生日」）。
2. 在 **系统默认日历** 中插入一条日程：
   - **开始时间** = 上述提醒时刻；
   - **标题**：如「距离「XXX」还有 N 天」；
   - **提醒**：0 分钟前（即到点提醒）。
3. 系统会在该时刻在 **通知栏** 提醒，用户也可在日历/日程应用中看到该条。

### 重复事件（生日等）

- **公历每年重复**：写入一条带 `RRULE=FREQ=YEARLY` 的日程，开始时间为「提醒日 + 提醒时刻」，系统会每年重复并在每年该时刻提醒。
- **农历每年重复**：每年公历日期不同，仅写入 **下一次** 提醒的日程（单次事件），不写 RRULE。

## 权限

- `READ_CALENDAR` / `WRITE_CALENDAR`：在用户开启「同步到系统日程」或保存带日程同步的提醒时，按需请求。

## 流程小结

1. 用户在 APP 内设置：提前 N 天、几点提醒、开启提醒、（可选）同步到系统日程。
2. 保存时：  
   - 照旧调度 **WorkManager**（应用内通知）；  
   - 若开启同步到日程，则向系统日历 **插入/更新** 对应日程，并保存返回的 `scheduleEventId`。
3. 到点：**系统日程** 触发通知栏提醒；**WorkManager** 也可再发一条应用内通知（可保留以便风格统一）。
4. 用户关闭提醒或关闭「同步到系统日程」时：删除对应系统日程（用 `scheduleEventId`），并清理 WorkManager。

## 与节点提醒的关系

- **单条事件提醒**：本事件自己的「提前 N 天 + 几点」→ 一条应用内提醒 + 可选一条系统日程。
- **节点提醒**（如 2000/1000 天）：仍在 **设置 → 节点临近提醒** 中配置，由 WorkManager 在对应日期的默认时刻触发，不写入系统日程（若后续需要也可再扩展）。

本方案仅针对「每个事件自己的提醒时间」与「同步到系统日程」的实现。
