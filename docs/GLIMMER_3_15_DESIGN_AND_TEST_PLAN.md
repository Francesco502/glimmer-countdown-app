# 拾光 3.15 设计方案与测试清单

目标版本：`3.15`  
文档日期：`2026-07-01`  
适用范围：拾光（Glimmer）Android App，覆盖首页近期信息组织、详情页、新增 / 编辑事件、设置页、应用图标与启动页。

## 一、版本定位

3.15 建议定位为一次“信息组织 + 宋式美学统一”的版本。

3.12 到 3.14 已连续补强了导入迁移、月历、小组件、设置结构、字体、透明背景和首页视觉层级。3.15 不应继续只做零散视觉微调，也不应贸然进入云同步、标签系统等高风险大改。更合适的方向是：

1. 让用户打开应用后更快知道“今天和近期有什么值得关注”。
2. 让详情、新建 / 编辑、设置、小组件、图标和启动页使用同一套纸墨视觉语言。
3. 让提醒、系统日程同步、小组件刷新等可靠性状态更可见。
4. 在不大改数据库的前提下，把已有能力组织得更完整、更稳定。

## 二、设计原则

### 2.1 宋式美学的边界

宋式美学不等于堆叠古风纹样。3.15 的视觉原则应是：

- 宣纸底色：暖白、旧纸、深墨纸作为主要背景层级。
- 淡墨层级：正文、辅助信息、分隔线、禁用态用不同透明度表达。
- 少量朱印：只用于分类、关键状态、品牌点睛，不大面积铺红。
- 青瓷辅助：用于次级强调、选中态、小组件风格和启动页辅助色。
- 细线分隔：用极细边线和留白建立秩序，减少厚重卡片堆叠。
- 克制动效：淡入、轻微位移、按压反馈即可，不做复杂装饰动画。

### 2.2 信息优先级

用户每天打开应用时，优先需要看到：

1. 今日事件。
2. 未来 7 天内事件。
3. 未来 30 天内事件。
4. 即将到来的生日、纪念日、倒数日。
5. 即将触发的重大节点，例如百日、周年、半岁、倒计时阈值。
6. 提醒与系统日程是否可靠。

界面美学服务于这些信息，不应让装饰压过时间信息。

### 2.3 低风险实现边界

3.15 不建议引入下列高风险范围：

- 云同步、账号体系、跨设备同步。
- 标签 / 分组数据模型大改。
- 新增复杂社交分享模板。
- 大规模重写导航结构。
- 大范围更换现有数据存储格式。

推荐优先复用现有 `EventUiState`、月历展开逻辑、重大节点计算、提醒和日程同步状态字段。

## 三、整体方案概览

3.15 可拆成七个设计模块：

1. 首页近期信息组织：新增“近期 / 今日”摘要能力。
2. 月历本月重点：在月历之外补充本月摘要。
3. 提醒可信度反馈：让通知、日程、权限、同步状态更透明。
4. 详情页事件帖：把详情卡片打磨成宋式“事件帖”。
5. 新增 / 编辑事件：从普通表单改为“书写 + 预览”的流程。
6. 设置页预览化：设置入口、外观、小组件、提醒状态都提供摘要和样张。
7. Icon 与启动页：完成品牌收口，保证小尺寸识别和主题一致。

## 四、首页近期信息组织

### 4.1 设计目标

首页需要从“事件列表容器”升级为“时间提醒入口”。用户打开应用后，应能立即回答：

- 今天有没有事件？
- 接下来一周有什么？
- 这个月有哪些重要日期？
- 有没有快到的生日、纪念日或重大节点？
- 哪些事件提醒已经开启，哪些可能不可靠？

### 4.2 推荐交互

保留现有“卡片 / 列表 / 月历”三种显示模式，同时新增一个轻量的近期摘要区。摘要区位于首页标题和模式切换下方、列表内容上方。若没有近期事件，摘要区自动收起或显示一行温和空状态。

近期摘要包含四类入口：

- 今日：显示今日事件数量和最重要的一条事件。
- 七日：显示未来 7 天内事件数量。
- 本月：显示当前月内生日、纪念日、倒数日数量。
- 节点：显示最近一个即将到来的重大节点。

点击摘要项后，不新建复杂二级页面，优先使用现有列表过滤和排序能力展示对应事件。后续若内容变多，再扩展为独立“近期”视图。

### 4.3 信息规则

今日事件优先级：

1. 今天正好发生的生日 / 纪念日。
2. 今天到期的普通倒数日。
3. 今天触发的重大节点。
4. 今天需要提醒但未开启通知权限的事件。

未来 7 天优先级：

1. 距离最近。
2. 生日和纪念日优先于普通倒数日。
3. 已置顶事件优先。
4. 提醒异常事件显示状态标记。

未来 30 天优先级：

1. 重大节点。
2. 周年、半岁、百日、千日等语义节点。
3. 普通倒数阈值，例如还有 7 天、30 天、100 天。

### 4.4 视觉表达

近期摘要不使用厚重卡片。推荐表现为“横向纸签”：

- 背景：比页面背景略深的宣纸色。
- 边框：0.5dp 淡墨线。
- 圆角：2-4dp，避免过强现代卡片感。
- 数字：使用宋体或当前字体体系的较大字号。
- 状态点：朱印色表示今日 / 重要，青瓷色表示普通近期。

## 五、月历本月重点

### 5.1 设计目标

3.14 已把月历日格减负，3.15 应补充“本月重点”区域，避免月历过于安静。用户进入月历后，应能在不逐日点击的情况下看到本月主要事件。

### 5.2 推荐内容

月历下方或选中日期列表上方增加“本月重点”：

- 本月生日。
- 本月纪念日。
- 本月倒数日。
- 本月重大节点。

每项最多展示 2-3 条，超过后显示“还有 N 项”。点击后展开当月完整列表。

### 5.3 数据规则

本月重点必须使用月历当前月份的完整展开结果，不能只使用首页截断后的 `MAX_UPCOMING_ITEMS` 数据。

需要覆盖：

- 一次性事件。
- 每日、每周、每月、每半年、每年重复事件。
- 农历每年重复事件。
- 已过事件在当前月内的发生日。
- 搜索、筛选条件对月历和本月重点同时生效。

## 六、提醒可信度反馈

### 6.1 设计目标

提醒能力已经包含应用内通知、系统日程同步、权限、可写日历、里程碑提醒、小组件刷新。3.15 应让用户知道“这条事件是否真的会提醒”。

### 6.2 事件级状态

详情页和编辑页显示轻量状态条：

- 应用提醒已开启 / 未开启。
- 通知权限正常 / 需要开启。
- 系统日程同步已开启 / 未开启。
- 系统日程最近同步成功 / 同步失败。
- 无可写日历时显示“日程不可用，但应用内提醒可用”。

状态条不应干扰主倒计时。推荐放在详情页卡片底部或信息区之后。

### 6.3 设置级状态

设置页新增“提醒与日程健康状态”：

- 通知权限。
- 日历读写权限。
- 是否存在可写日历。
- 最近一次系统日程同步时间。
- 最近一次同步失败原因。
- 里程碑提醒是否开启。

状态应以明确文本和图标表达，避免只用颜色。

### 6.4 异常处理

当提醒不可用时，用户应看到可执行操作：

- 打开通知权限。
- 打开日历权限。
- 关闭系统日程同步，仅保留应用内提醒。
- 重新同步系统日程。
- 查看最近同步失败的简短原因。

## 七、详情页事件帖

### 7.1 设计目标

详情页应从“普通详情卡片”打磨为“事件帖”。它需要庄重、清晰、安静，并把最核心的时间信息放到第一视觉层级。

### 7.2 信息结构

推荐结构：

1. 顶部元信息：分类朱印、日期、提醒状态。
2. 主标题：事件名称，最多 2-3 行。
3. 核心倒计时：还有 / 已经 / 今日，使用最大字号。
4. 语义说明：距离生日、纪念日、农历生日、下一次发生日等。
5. 重大节点：即将到来的百日、周年、半岁、倒计时阈值。
6. 日期事实：原始日期、公历 / 农历、重复规则、星座生肖等已有信息。
7. 备注题记：备注内容以题记样式显示。
8. 可靠性状态：提醒、通知权限、系统日程同步。
9. 操作区：编辑、置顶、删除等。

### 7.3 视觉规则

- 详情主容器使用宣纸或旧纸色，不使用纯白。
- 主倒计时使用淡墨深色，朱印色只用于关键标签或状态点。
- 分隔线使用极细淡墨线。
- 备注区行宽收窄，表现为题记，不做厚重文本框。
- 操作按钮弱化为图标按钮或底部工具栏，不破坏主卡片。
- 生日、纪念日、普通倒数日可以有轻微色调差异，但结构一致。

### 7.4 长内容规则

- 标题最长 3 行，超出省略。
- 备注支持多行，但超过合理高度后折叠，提供展开。
- 日期、重复规则、提醒状态不得被长标题挤出屏幕。
- 小屏设备上主倒计时字号需要降级，保证不溢出。

## 八、新增 / 编辑事件界面

### 8.1 设计目标

新增和编辑界面应从“参数表单”变成“书写事件”的流程，同时保持效率和可靠性。

### 8.2 顶部实时预览

页面顶部增加一个小型事件预览卡：

- 显示标题、分类、日期、颜色、重复规则、提醒状态。
- 标题为空时显示低干扰占位，例如“未题名事件”。
- 选择颜色、分类、公历 / 农历、重复规则时实时更新。
- 预览卡不承担保存功能，只帮助用户理解最终效果。

### 8.3 表单分组

表单分为四组：

1. 事件内容：标题、分类、备注。
2. 时间规则：日期、公历 / 农历、重复规则。
3. 提醒与日程：提醒开关、提前天数、提醒时间、系统日程同步。
4. 外观：颜色、显示样式相关选项。

每组使用细线标题和留白，不嵌套多层卡片。

### 8.4 模板入口

新建事件时提供三个轻量模板：

- 生日：默认分类生日，默认每年重复，可选择农历。
- 纪念日：默认分类纪念日，默认每年重复。
- 倒数日：默认分类其他，默认不重复。

模板只设置默认值，不创建额外数据结构。

### 8.5 日期选择

日期选择器继续保留公历 / 农历双模式，并强化“历书”感：

- 选中态使用淡青瓷或朱印细线，不使用过强填充色。
- 农历模式显示农历月份、闰月、日名。
- 公历和农历切换时保持日期语义清晰。
- 非法日期输入必须明确提示，不静默回滚。

### 8.6 颜色选择

颜色预设增加名称，推荐命名：

- 墨。
- 黛蓝。
- 松绿。
- 青瓷。
- 朱砂。
- 赭石。
- 旧金。
- 茶褐。
- 藕荷。

色块必须通过浅色和深色主题可读性检查。用户自定义颜色仍需保留对比度保护。

### 8.7 保存与权限

保存按钮继续固定底部，保证键盘弹出时可达。保存流程需要保留现有权限降级逻辑：

- 通知权限缺失时，可保存为不提醒。
- 日历权限缺失时，可保存为不同步日程。
- 保存部分成功时，明确显示影响范围。
- 旋转屏幕、返回、权限弹窗关闭都不能丢失用户输入。

## 九、设置界面

### 9.1 设置首页

设置首页保持分类入口，但每个入口增加当前状态摘要：

- 外观：跟随系统 / 浅色 / 深色、当前字体。
- 显示：日期格式、字号、密度。
- 里程碑与提醒：里程碑开关、默认提醒时间。
- 数据：最近导出 / 导入入口。
- 关于：版本号、更新渠道。

摘要只显示一行，避免设置首页变复杂。

### 9.2 外观设置

外观设置增加样张预览：

- 首页事件卡样张。
- 详情事件帖样张。
- 小组件样张。

用户调整字体、字号、颜色、主题时，样张即时反映变化。

### 9.3 显示设置

显示设置使用样例表达抽象选项：

- 日期格式示例。
- “还有 3 天 / 三日后 / 0 天今日”等倒计时示例。
- 密度示例。
- 里程碑展示示例。

### 9.4 小组件设置

小组件设置与 App 外观使用统一语言：

- 宣纸。
- 青瓷。
- 朱印。
- 透明。
- 半透明玻璃。

每个风格提供小预览，说明边框、圆角、文字对比、农历前缀、密度对显示的影响。

### 9.5 提醒与日程健康状态

设置页新增一组状态：

- 通知权限状态。
- 日历权限状态。
- 可写日历状态。
- 最近一次日程同步状态。
- 里程碑提醒状态。

用户可以从这里进入权限设置、重新同步或关闭系统日程同步。

## 十、Icon 与启动页

### 10.1 应用图标

当前“水墨沙漏 + 青瓷点”方向符合主题，但 3.15 应重点提升小尺寸识别。

推荐优化：

- 简化沙漏轮廓，使 48dp 和更小尺寸仍能识别。
- 保留青瓷点作为时间核心，但面积不宜过小。
- 朱印色只做点睛，不作为大面积背景。
- 背景使用温润纸色或低饱和青瓷。
- 单独制作 Android 13 themed icon 单色资源，不能依赖渐变。
- 检查深色模式、浅色模式、不同启动器图标遮罩下的显示。

可探索方向：

1. 沙漏 + 青瓷点。
2. 日晷 / 日影 + 朱印点。
3. 朱印中的“拾”或“光”。

推荐优先保留“沙漏 + 青瓷点”，因为它跨语言识别更稳定。

### 10.2 启动页

启动页目标是“轻仪式感”，不能拖慢工具型 App 的启动体验。

推荐优化：

- 图标尺寸从当前偏大的视觉占比收敛到更稳的品牌标识尺寸。
- 背景使用应用同源宣纸色，深色模式使用深墨纸。
- 显示“拾光”字标和一句短副标，副标不抢主视觉。
- 动效控制在 600-900ms 体感范围内。
- 数据加载较慢时，启动页平滑过渡到首页，不强制播放完整动画。

## 十一、组件与架构建议

### 11.1 建议沉淀的组件

后续实现时建议沉淀以下组件：

- `SongPaperSurface`：继续作为纸面容器基础。
- `SongSectionHeader`：设置、详情、编辑页分组标题。
- `SongSealLabel`：分类、重要状态、品牌点睛。
- `SongTimelineDigest`：近期摘要。
- `SongMonthHighlights`：本月重点。
- `SongReminderStatusStrip`：提醒可信度状态条。
- `SongEventPreviewCard`：新增 / 编辑实时预览。
- `SongBottomActionBar`：详情和编辑页底部操作。

### 11.2 数据来源

优先复用已有数据：

- `EventUiState`：倒计时、已过天数、下一次发生日、重大节点。
- 月历展开模型：本月重点数据来源。
- `Event` 提醒字段：提醒开关、提前天数、提醒时间、日程同步状态。
- `lastScheduleSyncAt` 和 `lastScheduleSyncError`：日程同步状态。
- 用户偏好：主题、字体、字号、显示模式、小组件配置。

### 11.3 数据库迁移

本方案不要求数据库迁移。若实现过程中必须新增持久化偏好，应优先使用 DataStore，不修改 `Event` 表。

## 十二、必须通过的测试列表

### 12.1 自动化测试命令

发布 3.15 前必须通过：

```bash
./gradlew testDirectDebugUnitTest
./gradlew testPlayDebugUnitTest
./gradlew compileDirectDebugAndroidTestKotlin
./gradlew lintDirectRelease lintPlayRelease
./gradlew assembleDirectRelease assemblePlayRelease bundlePlayRelease
```

Direct / Play 权限与产物检查必须通过：

- Direct APK 包含 `REQUEST_INSTALL_PACKAGES`。
- Play APK 不包含 `REQUEST_INSTALL_PACKAGES`。
- Direct APK 文件名符合 `glimmer-countdown-3-15.apk`。
- Play AAB 输出到 `app/build/outputs/bundle/playRelease/app-play-release.aab`。
- GitHub Release 资产只包含 Direct APK。

### 12.2 新增或扩展的单元测试

首页近期摘要：

- 今日事件正确进入“今日”摘要。
- 未来 7 天事件正确进入“七日”摘要。
- 未来 30 天事件正确进入“本月 / 近期”摘要。
- 生日、纪念日优先级高于普通倒数日。
- 已置顶事件在同等日期下优先展示。
- 搜索条件会影响近期摘要。
- 分类筛选会影响近期摘要。
- 无近期事件时摘要收起或显示正确空状态。
- 过去事件不会错误进入未来摘要。
- 每年重复事件使用下一次发生日计算。
- 农历每年重复事件使用农历下一次发生日计算。

本月重点：

- 一次性事件在对应月份显示。
- 每周重复事件在本月所有发生日显示。
- 每月重复事件在短月份和长月份显示正确。
- 每半年重复事件跨年显示正确。
- 每年重复事件显示在正确月份。
- 农历每年重复事件按转换后的公历月份显示。
- 当前月切换后，本月重点重新计算。
- 搜索、筛选与月历日格、本月重点保持一致。

重大节点：

- 生日优先展示半岁、周年等语义节点。
- 纪念日优先展示周年节点。
- 普通倒数日优先展示倒计时阈值。
- 自定义节点仍可覆盖或进入候选。
- 无即将到来的节点时不显示“0 天”误导文案。

提醒可信度：

- 通知权限关闭时状态为“需要开启通知权限”。
- 通知权限开启但事件提醒关闭时状态为“未开启提醒”。
- 系统日程同步关闭时不显示同步失败。
- `lastScheduleSyncError != null` 时显示失败状态。
- 无可写日历时显示“日程不可用，但应用内提醒可用”。
- 重新同步后状态正确刷新。

详情页展示模型：

- 长标题最多 3 行并省略。
- 今日事件显示“今日”而不是“0 天”。
- 农历生日显示农历语义。
- 备注为空时不显示空题记区域。
- 备注过长时折叠状态正确。
- 提醒状态条不影响主倒计时计算。

新增 / 编辑事件：

- 生日模板默认分类为生日，默认每年重复。
- 纪念日模板默认分类为纪念日，默认每年重复。
- 倒数日模板默认分类为其他，默认不重复。
- 公历 / 农历切换后保存的 `isLunar` 正确。
- 颜色预设名称与色值映射正确。
- 保存权限降级不会丢失表单输入。
- 编辑已有事件时不覆盖原有提醒配置。

设置页：

- 设置首页摘要与当前偏好一致。
- 外观预览随主题、字体、字号变化。
- 显示设置样例随日期格式变化。
- 小组件预览随默认配置变化。
- 提醒健康状态随权限和同步结果变化。

视觉与主题：

- 浅色主题下主要文本对比度达标。
- 深色主题下主要文本对比度达标。
- 朱印色不作为大面积正文背景。
- 青瓷色选中态在浅色 / 深色都可读。
- 字体切换到 Noto Serif SC、ZCOOL XiaoWei、系统黑体、系统衬线、默认字体后不溢出。

Icon 与启动页：

- adaptive icon 前景和背景资源存在。
- themed icon 单色资源存在。
- 图标 vector 不引用缺失资源。
- 启动页文案中英文资源完整。
- 启动页动画结束后必定进入主界面。

## 十三、发布验收标准

3.15 可以发布的最低标准：

1. 所有自动化测试命令通过。
2. 新增近期摘要、本月重点、提醒可信度相关测试通过。
3. 首页、详情、新建 / 编辑、设置、启动页在浅色和深色主题下均无明显溢出。
4. Noto Serif SC、ZCOOL XiaoWei、系统黑体、系统衬线、默认字体均可正常显示。
5. Direct / Play 渠道权限和更新入口符合渠道规则。
6. 小组件核心能力无回归。
7. 导入导出无回归。
8. Android 13 themed icon 和普通 adaptive icon 均可识别。
9. 手动回归未发现阻塞级问题。

## 十四、建议实施顺序

1. 先沉淀视觉组件和状态模型：近期摘要、本月重点、提醒状态条、事件预览卡。
2. 实现首页近期摘要和月历本月重点，因为它们最能提升日常使用价值。
3. 打磨详情页事件帖，统一主次、备注、状态和操作区。
4. 打磨新增 / 编辑页，引入实时预览、模板和分组。
5. 打磨设置页摘要、预览和提醒健康状态。
6. 重做 Icon 细节和启动页，作为 3.15 品牌收口。
7. 补齐自动化测试、人工测试清单和发布文档。

## 十五、非目标

3.15 不处理：

- 云同步。
- 账号登录。
- 标签和多级分组。
- 社交分享海报系统。
- 大规模数据库结构重构。
- 全新小组件架构。

这些功能可以在 3.16 或更后续版本单独设计。
